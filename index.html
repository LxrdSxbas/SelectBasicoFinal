Sección 01 Sintaxis Fundamental

Introducción — SELECT y FROM

La estructura atómica de cualquier consulta de datos en Oracle SQL: seleccionar qué columnas visualizar y de qué relación extraerlas.

Toda consulta de recuperación en Oracle SQL inicia conceptualmente con la necesidad de consultar datos almacenados en una tabla. Para lograrlo, se utilizan dos palabras clave obligatorias: SELECT, que indica qué columnas o atributos se desean proyectar en la salida, y FROM, que especifica la tabla física de donde provienen los registros.

Si se necesita recuperar todas las columnas de la tabla sin especificarlas una por una, se utiliza el carácter comodín asterisco (*). Sin embargo, en buenas prácticas de ingeniería y optimización, siempre es preferible proyectar únicamente las columnas estrictamente necesarias, separándolas mediante comas.

Adicionalmente, Oracle permite asignar nombres temporales a las columnas resultantes mediante la cláusula AS (o simplemente un espacio). A esto se le conoce como Alias de Columna, muy útil para hacer que los encabezados del reporte sean más descriptivos y legibles para el usuario final.

💡
Regla de oro: Aunque escribimos SELECT primero y FROM después, Oracle ejecuta en su motor interno primero la cláusula FROM para cargar la tabla en memoria antes de extraer las columnas solicitadas.
📜 Ejemplo de Sintaxis: Proyección con Alias
SELECT nombre, apellido, carrera, promedio AS calificacion_actual
FROM ESTUDIANTES;

Sección 02 Eliminación de Duplicados

Deduplicación de Tuplas con DISTINCT

Cómo filtrar duplicados para obtener listas únicas de valores o combinaciones de atributos en Oracle SQL.

En una base de datos relacional, una tabla contiene múltiples filas que frecuentemente comparten datos repetidos en ciertos campos. Por ejemplo, en una universidad con miles de alumnos, el atributo carrera o ciudad tendrá decenas de valores repetidos como "Sistemas" o "Bogotá".

La palabra clave DISTINCT se coloca inmediatamente después de SELECT para indicarle a Oracle que elimine todas las tuplas idénticas del conjunto resultante, retornando una única fila por cada combinación exclusiva de valores encontrados.

Es vital comprender que DISTINCT evalúa la fila proyectada en su totalidad: si proyectas SELECT DISTINCT carrera, ciudad, una fila solo se considerará duplicada si ambos campos (carrera y ciudad) son exactamente iguales a otra fila previa.

💡
Impacto en el Pipeline: La deduplicación DISTINCT se ejecuta después del filtrado WHERE y antes de ordenar el resultado con ORDER BY.
📜 Ejemplo de Sintaxis: Carreras Universitarias Únicas
SELECT DISTINCT carrera
FROM ESTUDIANTES;

Sección 03 Filtro Horizontal Relacional

Filtrado con WHERE y Operadores de Comparación

La cláusula fundamental para discriminar tuplas mediante condiciones booleanas precisas: `=`, `<`, `>`, `<=`, `>=`, `<>` y `!=`.

En bases de datos no siempre queremos ver todas las filas registradas. La cláusula WHERE actúa como un filtro horizontal (equivalente al operador de selección σ en álgebra relacional) que evalúa una condición fila por fila. Si la condición resulta en VERDADERO (TRUE), la tupla se conserva; si resulta en FALSO, se descarta inmediatamente.

Para formular estas condiciones, Oracle dispone de operadores de comparación fundamentales: igualdad (=), desigualdad estándar (<> o !=), y comparaciones de orden numérico o temporal: menor que (<), mayor que (>), menor o igual (<=) y mayor o igual (>=).

Los valores numéricos se escriben directamente sin comillas (por ejemplo, promedio >= 4.0), mientras que las cadenas de texto (literales alfanuméricos) deben encerrarse estrictamente entre comillas simples (como carrera = 'Sistemas').

💡
Orden Lógico: La cláusula WHERE se ejecuta inmediatamente después de FROM. Esto significa que Oracle primero descarta las filas no deseadas antes de gastar recursos proyectando columnas o eliminando duplicados.
📜 Ejemplo de Sintaxis: Estudiantes de Cuadro de Honor
SELECT nombre, apellido, carrera, promedio
FROM ESTUDIANTES
WHERE promedio >= 4.5;

Sección 04 Lógica Booleana Compuesta

Operadores Lógicos: AND / OR y Precedencia

Cómo combinar múltiples condiciones lógicas, controlar la precedencia de operadores y evitar ambigüedades mediante el uso correcto de paréntesis.

Cuando los requerimientos de consulta exigen validar más de un criterio a la vez, recurrimos a los conectores booleanos AND y OR. El operador AND exige que ambas condiciones sean verdaderas simultáneamente para que la fila sea seleccionada; mientras que el operador OR aprueba la fila si al menos una de las condiciones se cumple.

Un aspecto crítico y fuente habitual de errores es la precedencia de operadores. En SQL, el operador AND tiene una jerarquía superior y se evalúa estrictamente antes que el OR, de manera similar a como la multiplicación matemática se resuelve antes que la suma.

Para modificar el orden natural de evaluación o garantizar una intención clara y libre de ambigüedades, se deben emplear **paréntesis** (...). Toda condición encerrada entre paréntesis se evalúa de manera prioritaria como una unidad lógica independiente.

💡
Ejemplo de Precedencia: carrera = 'Sistemas' OR carrera = 'Medicina' AND promedio >= 4.5 se interpreta internamente como "Sistemas (con cualquier promedio) O (Medicina con promedio >= 4.5)". Para exigir el promedio alto a ambas carreras, es indispensable agrupar: (carrera = 'Sistemas' OR carrera = 'Medicina') AND promedio >= 4.5.
📜 Ejemplo de Sintaxis: Agrupamiento con Paréntesis
SELECT nombre, carrera, promedio, ciudad
FROM ESTUDIANTES
WHERE (carrera = 'Sistemas' OR carrera = 'Industrial')
  AND promedio >= 4.0;

Sección 05 Rangos Continuos Inclusivos

El Operador BETWEEN: Rangos Cerrados

Cómo evaluar si un atributo se encuentra dentro de un intervalo cerrado de valores numéricos, fechas o texto.

El operador BETWEEN ... AND ... se emplea para comprobar de manera elegante y concisa si el valor de una columna se encuentra dentro de un rango específico determinado por dos límites: un límite inferior y un límite superior.

Una propiedad vital y obligatoria de recordar en Oracle SQL es que **BETWEEN es completamente inclusivo**. Es decir, la condición semestre BETWEEN 3 AND 6 equivale de manera idéntica y estricta a escribir: semestre >= 3 AND semestre <= 6. Tanto el 3 como el 6 están incluidos en los resultados.

Es imperativo que el primer valor especificado sea el menor y el segundo el mayor. Si se escribe erróneamente un orden invertido como semestre BETWEEN 6 AND 3, la condición evaluará siempre a FALSO en Oracle, ya que ningún número puede ser simultáneamente mayor o igual a 6 y menor o igual a 3.

💡
Negación: También es posible utilizar NOT BETWEEN valor1 AND valor2 para encontrar registros que se ubiquen estrictamente por fuera del rango establecido.
📜 Ejemplo de Sintaxis: Estudiantes de Mitad de Carrera
SELECT nombre, apellido, semestre, promedio
FROM ESTUDIANTES
WHERE semestre BETWEEN 4 AND 7;

Sección 06 Conjuntos Discretos de Valores

El Operador IN: Pertenencia a Conjuntos

Cómo evaluar si un valor coincide con cualquiera de los elementos listados dentro de un conjunto delimitado entre paréntesis.

Cuando necesitamos verificar si el valor de una columna coincide con una de varias opciones posibles, escribir múltiples cláusulas con OR (como ciudad = 'Bogotá' OR ciudad = 'Medellín' OR ciudad = 'Cali') se vuelve repetitivo, extenso y propenso a equivocaciones sintácticas.

Para solucionar esto, Oracle proporciona el operador IN. Su sintaxis consiste en indicar el nombre de la columna seguido de la palabra clave IN y una lista de valores separados por comas encerrados entre paréntesis: columna IN (valor1, valor2, valor3).

La consulta evalúa a VERDADERO si el valor de la fila es idéntico a cualquiera de los elementos contenidos en la lista. Además de mejorar drásticamente la legibilidad del código, el optimizador de Oracle suele procesar la lista IN con alta eficiencia indexada.

💡
Equivalencia Lógica: carrera IN ('Sistemas', 'Medicina') es conceptualmente idéntico a (carrera = 'Sistemas' OR carrera = 'Medicina').
📜 Ejemplo de Sintaxis: Sedes Principales
SELECT nombre, carrera, ciudad
FROM ESTUDIANTES
WHERE ciudad IN ('Bogotá', 'Medellín', 'Cali');

Sección 07 Búsqueda de Patrones Textuales

Búsqueda de Patrones con LIKE (% y _)

Cómo buscar coincidencias parciales de texto utilizando los comodines universales de Oracle SQL: porcentaje y guión bajo.

En muchas situaciones de negocio o académicas no conocemos el valor textual exacto que buscamos, o deseamos recuperar todas las palabras que comiencen, contengan o finalicen con determinada secuencia de letras. Para este propósito, Oracle dispone del operador de comparación de cadenas LIKE.

El operador LIKE trabaja en conjunto con dos comodines fundamentales:

  • % (Signo de Porcentaje): Representa cero, uno o múltiples caracteres arbitrarios. Por ejemplo, 'A%' coincide con cualquier texto que empiece con "A" (como "Alejandro", "Ana" o simplemente "A").
  • _ (Guión Bajo): Representa exactamente un único carácter. Por ejemplo, 'SIS___' coincide con la palabra SIS seguida de exactamente 3 caracteres más (longitud fija de 6 caracteres, como "SIS101").

Si buscas una subcadena en cualquier posición dentro del texto, rodea el término con porcentajes a ambos lados: LIKE '%Datos%'.

💡
Diferencia clave: = 'A' exige coincidencia exacta con la letra A sola. LIKE 'A%' exige únicamente que la letra inicial sea A, sin importar cuántos caracteres le sigan.
📜 Ejemplo de Sintaxis: Cursos del Área de Sistemas
SELECT id_curso, nombre_curso, departamento
FROM CURSOS
WHERE id_curso LIKE 'SIS%';
